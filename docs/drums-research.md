# FN ACID 鼓机调研：X0X 的 808 / 909 怎么做，FN ACID 怎么加

2026-10-20。只做调研，没有改代码。X0X 源码位置：`scratchpad/repos/x0x`（charlesvestal/fm1-x0x）。下文 `x0x:` 开头的路径都相对这个仓库，`fa:` 开头的指 `D:\claude\function-acid-fw`。

---

## 0. 先看三条结论

1. **许可证可以直接搬代码。** X0X 是 GPL-3.0-only（`x0x:LICENSING.md`），FN ACID（从 Dinghy 分叉）也是 GPL-3.0-only（`fa:LICENSING.md`），两边兼容。909、808 的 DSP 代码和 909 镲片采样（ER-99 的 hh/ride/crash，GPL-3.0）都能照搬，条件有三：保留原有的版权和 SPDX 头；在 `fa:LICENSING.md` 里补上来源（X0X ← 9W9 ← ER-99；X0X ← 8W8，rim 来自 sc808）；发布固件时附完整源码（我们本来就这么做）。break 生成器是作者单独授权给 X0X 的，用不到，也不要碰。TR-808 / TR-909 是 Roland 商标，只能用来说明是在模仿什么，界面上写 "909"、"808" 就行，X0X 也是这么写的。
2. **"没有 FPU"这个前提可能不成立。** `fa:docs/RULES.md` 写的是 no FPU、禁 float。但 X0X 在同一块芯片（AC79 / pi32v2）上，用 `-mcpu=r3 -mfprev1 -ffp-contract=off` 打开了单精度硬件 FPU（`x0x:tools/build.py:40-42`）。它的设计文档说，这个 FPU 直接用通用寄存器运算，中断里不用额外保存状态（`x0x:docs/plans/2026-10-03-x0x-design.md:17`）。我们的 `fa:tools/build.py:40` 只是没加这几个 flag。如果给"鼓"这一个编译单元单独加上，X0X 的 float 代码几乎能原样移植。**这一点要先编个小测试上机验证**，验证通过以后 RULES.md 也要跟着改。不能用 FPU 的话，909 改成定点还算可行，808 很难（第 3.6 节）。
3. **存储比 CPU 更紧。** `params_t` 我按字段手算是 **472 字节**；`store_t` = 当前状态 + 7 个槽位 = 8 份 + 8 字节 = 3784 B，上限是 4084 B（`fa:firmware/src/dinghy.c:28-53`）。所以 `params_t` 每份只剩约 **37 字节**余量，而且每加 1 字节就要乘 8。加鼓机必须先定存储方案（第 3.4 节）。

## 1. X0X 的 909 和 808 声音是怎么做的

### 1.1 共同点

- 两台都是单声道、44.1 kHz、float、不用 libm、不分配内存。只算还在发声的 voice，没在响的 voice 一点 CPU 都不占（`x0x:firmware/src/dsp/drum909.h:9-11`、`drum808.h:16-18`）。
- 两台都是 11 条轨，一条轨对一个黑键。808 有些轨能切换声音：Tom/Conga、Rim/Clave、Clap/Maracas，一共 16 种声音（`drum808.h:10-14, 25, 35-36`）。
- 数学库是 `x0x:firmware/src/dsp/fastmath.h`：exp2、log2、sin、tanh 等全部 static inline，在主机上逐位验证过误差。
- 旋钮值存成 0..127，再通过表或公式换成工程单位（ms、Hz、倍数）。

### 1.2 909（`dsp/drum909.c`，从 9W9 / ER-99 移植的电路模型）

用到的积木在 `dsp/drum909_dsp.h`：

| 积木 | 做法 | 行号 |
|---|---|---|
| 指数包络 | 模仿 Web Audio 的 exponentialRamp。每个采样做一次 `v *= r`，每块开头用 `exp2` 按闭式重新对齐一次，误差不会累积超过一块 | drum909_dsp.h:64-129 |
| 振荡器 | uint32 相位（2^32 = 一个周期）出三角波，`D9_PHASE_PER_HZ = 2^32/44100` | :36, 179-186 |
| tanh | 1025 点查表 + 线性插值，覆盖 [0, 8]，误差小于 6e-6；二极管削波和所有饱和器都用它 | :191-203 |
| 失真 | 7 种：Diode（默认）、Clip、SAT、BFZ、PDIST、Fold、Crush | :208-297 |
| 噪声 | xorshift32。所有 voice 共用一个噪声块，并保留 256 点历史，用来让滤波器"热身" | :302-310, drum909.c:771-782 |
| 双二阶滤波 | RBJ 直接 I 型；cos(w0) 写成 1 − 2sin²(w0/2)，保住 20 Hz 隔直滤波器的精度 | :136-174 |

各个 voice（默认值见 `drum909.c:259-359`，旋钮表见 `:50-92`）：

| Voice | 算法 | 旋钮 | 行号 |
|---|---|---|---|
| **BD** | 三角波从 0.25 相位起振。频率 = 49 Hz × 基频倍数 + df，df = 4.6 Hz/ms × τ，先保持 16 ms 再按 τ 指数下降。之后过二极管 `tanh(1.6x)`，加 0.05x² 做一点不对称，再过 20 Hz 隔直和失真级。振幅包络先保持 40 ms，再按 DECAY 指数衰减。CLICK = 2 个采样的冲击 + 低通（2.5 kHz）噪声，3 ms 包络，乘 ATTACK | TUNE（其实是扫频时间常数 τ，6–32 ms）、ATTACK（click 0–1）、DECAY（100–4000 ms，指数）、LEVEL、P.DPTH、PITCH（基频 ×0.43–4.7）、DRIVE、DIST | trig 364-399, render 538-581 |
| **SD** | 两个三角波"鼓壳"：tune 和 tune×1.585，第二个混 0.40，各自过二极管 `tanh(2x)`。音高从 1.045 倍扫回原位，用时 30 ms。噪声先过 1 kHz 高通、再过 6.5 kHz 低通，包络先保持 24 ms 再衰减，乘 SNAPPY×1.95 | TUNE（130–320 Hz）、TONE（其实是噪声衰减时间，300–4000）、SNAPPY、DECAY（120–800 ms，原版固定 340） | 442-455, 585-621 |
| **LT/MT/HT** | 三个三角波，频率 ×1、×1.5、×2.75，包络分别是 DECAY、110 ms、70 ms。音高从 1.12 倍扫回 tune。"鼓棒"噪声过 1.2 kHz 带通，8 ms。高次泛音衰减完就不再计算 | TUNE、DECAY、LEVEL、ATTACK（鼓棒声量） | 401-423, 626-667 |
| **RS** | 冲击 + 0.35 倍噪声，送进两个带通（tune 和 tune×2.286，Q 10/11），分别乘 60 和 32，200 ms 包络，过二极管，再过 120 Hz 高通 | LEVEL、TUNE（150–300 Hz）、DRIVE | 459-474, 670-688 |
| **CP** | 4 次噪声脉冲，间隔 12 ms，幅度 1.22/1.35/1.68/1.0，每次 50 ms 衰减；然后一段尾音（电平 0.58，345 ms）。全部过 950 Hz 带通（Q 2）和 400 Hz 高通。**默认 LEVEL 旋钮 122、DRIVE 1.6**，这是它刺耳的直接原因 | LEVEL、TUNE、TAIL、DRIVE | 475-483, 691-718；默认值 76, 322-333 |
| **CH/OH** | **采样**：两者共用一段 hh 采样（20 250 帧，8-bit μ-law），各套一个指数包络（CH 110 ms、OH 450 ms）。一个响起时，另一个在 3 ms 内淡出（互相掐断） | DECAY、LEVEL、TUNE（变速 0.25–4，32.32 定点读位置 + 线性插值） | 484-499, 721-748 |
| **CR/RD** | 同样是采样：crash 43 300 帧、ride 46 999 帧，衰减 1800 ms | TUNE、LEVEL、DECAY | 同上 |

- **重音**：`vgain = accent × (1 − vel_depth × (1 − vel))`（`drum909.c:431`）。KIT 页的 ACCENT 范围 1–4，默认旋钮 42 ≈ 2.0（`:91`）。音序器给没有重音的步 vel = 88/127，大约比重音低 3 dB（`x0x:firmware/src/seq/sequencer.c:25, 142`）。重音行是"整步重音"，一步上所有鼓一起变响。
- **内存**：`drum909_t` 里的大头是 3 KB 的噪声缓冲（768 个 float），整个结构约 5 KB。表：tanh 1026 个 float ≈ 4 KB；19 条旋钮指数曲线 × 128 个 float ≈ 9.7 KB（`x0x:tools/gen_drum_samples.py:34-46`）；μ-law 解码表 512 B。**采样**（hh 20 250、ride 46 999、crash 43 300 帧，μ-law 1 字节/帧）合计约 **110 KB 闪存**，由 `tools/gen_drum_samples.py` 生成。

### 1.3 808（`dsp/drum808.c`，从 8W8 / sc808 移植的电路模型）

基本做法：大多数声音是"**桥 T 带通 + 反馈环**"。触发时给一个 44 个采样（1 ms）的门脉冲，脉冲电压就是重音电压，激励一个高 Q 带通；反馈环的增益决定共鸣多久。重音不只是改音量：它改变激励电压，经过 op-amp 削波（`opamp_clip` = rail×tanh）之后，**音色也会跟着变**。

| Voice | 算法 | 行号 |
|---|---|---|
| **BD** | 带通（Q 2.356），频率 = MIDI 34 + TUNE（约 58 Hz），反馈环增益 = 500 k 电位器 / (47 k + 电位器)，相当于 DECAY。有一个"叹气"效果：声音大时频率抬高约 16%。ATTACK 会短暂抬高 f 和 Q，并加 click。TONE 是一阶低通，300 Hz × 20^tone。滤波系数每 16 个采样才重算一次 | 433-489 |
| **SD** | 两个带通鼓壳：173 Hz（Q 17.4）和 336 Hz（Q 10.7），用 sin/cos 按 TONE 混合，过 op-amp 削波（rail 40）。噪声先半波整流，乘 75 ms×DECAY 的指数包络，再过 1760 Hz 高通；SNAPPY 控制噪声量 | 514-555 |
| **Tom/Conga** | 带通 + 反馈，增益由响铃时长算出；音高包络 +8.5%（tom）或 +3%（conga）；tom 多一层"鼓皮"噪声 | 571-629 |
| **Clave** | 2.5 kHz 高 Q 带通 + 反馈 | 635-670 |
| **Maracas** | 噪声过两个一阶高通（6.3 k 和 4.6 k），有起音（约 1.2 ms×a²）和衰减。**很轻、很短** | 682-712 |
| **RS** | sc808 的做法：三角波 + 占空比 80% 的方波，过 464 Hz 峰值 EQ，再过高通和低通；包络 2.7 ms 起音 + 衰减 | 718-765 |
| **CP** | 3 个"齿"（间隔 10 ms），第 2.8 个间隔处打开主包络，再加一层底噪；噪声整流后过 874 Hz 带通（Q 1.29）和 720 Hz 高通 | 771-817 |
| **金属声源** | 6 个施密特方波，频率 206/368/306/521/803/542 Hz（808 原版那组），带 polyBLEP 抗混叠、慢漂移和抖动，0.32 定点相位。只要 CB/CH/OH/CY 有一个在响就要跑 | 820-878 |
| **CH/OH** | 金属声源 → 二次差分 ×30 → 二极管拐点门（`knee_gate`）→ 两级 Sallen-Key 高通（CH 5.2 k/2.7 k，OH 6.2 k/5.2 k）→ CH 1 级、OH 5 级一阶低通。OH 的包络先保持 30% 再线性放电。CH 默认掐断 OH | 989-1078, 1484-1486 |
| **CY** | 金属声源 → Werner 三阶带通 ×2 → 三条包络、三个频段（sustain / body / top）；**最贵的一个** | 903-986 |
| **CB** | 803 和 542 Hz 两个方波 → 812 Hz 带通（Q 5.5），叠加"哐"和"身"两段包络，再加一点二次项 | 1080-1125 |

- **旋钮**（`drum808.c:1202-1220`）：每个声音都有 LEVEL、TUNE、DECAY；另有 X1/X2 两个附加位（BD 的 TONE/ATTACK，SD 的 SNAPPY/TONE，MA 的 ATTACK）；DRIVE/DIST 放在列表的"MORE"里。各轨的平衡系数 `k_trim` 在 `:1222-1225`。
- **重音**：`vgain = 1.992 × (1 − vel_depth(1 − vel))`，再换成触发电压 4–14 V（`:1461-1465`）。不带重音的一步在 vel 0.502（`drum808.h:30`，换算见 `x0x:firmware/src/app/engine.c:364`）。
- **节省 CPU**：尾音低于峰值 60 dB 就停止计算。过载保护把这个"安静"门槛从 3.2e-5 提到 3.2e-3（`engine.c:88`）。

### 1.4 CPU 和代码大小（X0X 自己的测量）

`x0x:docs/plans/2026-10-04-performance.md:23-52` 和 `docs/MANUAL.md:659`：

- 主机上每个采样的耗时（ns，只看比例）：**909 普通 22 / 最密 54；808 普通 9（没在响）/ 全开 88 / 最密 171**。808 单个 voice 发声时：CY 53、BD 35、SD/CB/OH/toms 约 20、CP/RS/CH 不到 5。
- 设备单核实测：出厂 loop（909 + 303 + break + 效果 + 母线）**43%**，最坏情况 115%（所以 X0X 把 808 挪到了第二个核上）。
- 粗略换算：出厂 loop 约 161 主机-ns 对应设备 43%，也就是 1 ns ≈ 0.27%。照此，**909 普通约 6%、最密约 14%；808 普通鼓组约 15–25%，最密约 45%**。这是估算，要以上机实测为准。
- 代码大小（-O2）：**909 约 10.3 KB**（`drum909_render` 一个函数 8.8 KB），**808 约 7.8 KB**。I-cache 32 KB，代码从 XIP 闪存执行，缓存竞争只能上机测。

## 2. X0X 的鼓音序和界面

- **按键**（`MANUAL.md:104-140, 222-265`）：16 个白键 = 16 步（OCT± 每次翻 16 步，最多 64 步）；11 个黑键 = 11 条鼓轨。停止时按黑键选轨会出声，播放时选轨是静音的，免得多打一下（GLO > KEY SOUND 可以改）。在白键上轻按一下就切换这一步的开关。**按住 ENV + 白键 = 写重音**；按住 ENV + 黑键 = 现场打一下重音。按住 HOME + 黑键 = 静音这条轨（静音不保存）。开着 REC 时，黑键可以现场录入。
- **网格**（`x0x:firmware/src/app/ui.c:3010-3052`）：主区域是两条 69 px 的带（`:2579`），12 行（11 条轨 + AC），每行 11 px；左边 24 px 写轨道名，选中的轨反色显示；格子 12×9 px，列位置 `x = 27 + c×13 + (c>>2)`（拍与拍之间多空 1 px）；AC 行用白色小块；播放头所在的格子里画一个白色内框；有 p-lock 的步在角上画一个小缺口；静音的行变灰。底栏写"BLACK: TRACK, WHITE: STEP"。
- **键灯**（`MANUAL.md:168-185`）：亮 = 当前轨有音的步和当前轨；暗 = 其他有音的轨。
- **页面**：EDIT 进当前轨的音色页（909 BD 有两页），然后是 KIT 页（ACCENT）。SEQ 页是 LENGTH 和 RATE。SWING 放在 HOME，因为它作用于所有部分。DRIVE/DIST 放在 SEL 的列表里。
- **调音台**：按 LFO 进入 909 MIX / 808 MIX，11 条轨的电平一屏显示；黑键选轨，旋钮调 LEVEL / PAN / REV / DLY。
- **一个 pattern 里存什么**（`x0x:firmware/src/seq/pattern.h:12-77`）：32 个 pattern × 64 步。一台鼓机一个 pattern 是 `dpart_t` = 11 条轨 × 2 个 32 位字 + 重音 2 个字 + 长度、速率 = **100 字节**。909 和 808 同时存在于每个 pattern 里。每一步只有"开/关"，力度只来自整步重音行。概率和 p-lock 存在单独的 motion 数据里。
- **闪存**（`x0x:firmware/src/app/project.c:1-31`、`storage.c:1-25`）：设置和音色各占一个对象；patterns + song + motion 原始约 30 KB，LZ 压缩后跨 4 个对象存放（容量 4 × 3836 − 12 ≈ **15.3 KB**）。每个对象有 A/B 两个扇区，头部带序号和 CRC，写坏了就回退到上一份；内容没变的对象不重写。停止 4 秒没人操作就自动保存；**播放时不保存**（擦闪存会卡住声音）。

## 3. FN ACID 的方案

### 3.1 定位：T3 KICK 改成 T3 DRUMS，"四条轨"不变

- T3 的名字改成 **DRUMS**，加一个 **KIT** 参数：`FUNCTION`（现在的音高尖峰 kick，行为完全不变，也是旧存档读进来的默认值）/ `909` / `808`。
- T1 ACID、T2 BIO、T4 PERC 不动。T4 继续负责"自然声"（蟋蟀、蝉、噪声镲）。如果 KIT 不是 FUNCTION，建议 T4 默认换成蟋蟀或蝉，免得和鼓机的 CH/OH 叠成两层镲。
- DUCK 继续用 `kDuck`。改成 BD 一触发就开一个闪避包络，三个 kit 都由 BD 来触发闪避。
- 鼓保持干声，不进 delay/reverb，和现在的设计一致（`dinghy.c:774`）。

### 3.2 Voice 列表（10 行 + AC = 11 个黑键）

| 行 | FUNCTION（新写，整数） | 909（移植） | 808（移植） |
|---|---|---|---|
| 1 BD | 现在的 `eval_kick` | BD | BD |
| 2 SD | 音高尖峰正弦 + 高通噪声 | SD | SD |
| 3 LT | 尖峰 kick 调高、body 变短 | LT | LT / LC |
| 4 HT | 同上，再高一些 | HT | HT / HC |
| 5 RS | 1.2 kHz 两周期短"嗒" | RS | RS / CLAVE |
| 6 **SOFT** | SHAKER | SHAKER / SNAP / BRUSH | MARACAS / CLAVE |
| 7 CH | T4 的噪声镲代码（抽成共用函数） | CH（采样） | CH |
| 8 OH | 同上，长衰减 | OH（采样，和 CH 互相掐断） | OH |
| 9 CY | 6 个整数方波（808 那组频率）+ 高通 | RD 或 CR（采样，二选一） | CY（贵，见 3.5） |
| 10 CB/MT | 540 + 800 Hz 两个方波 + 带通 | MT | CB |
| 11 AC | 重音行 | 重音行 | 重音行 |

**不做拍手，用"SOFT"这一行代替**（用户嫌拍手"太吵/灾难"）。X0X 的 909 CP 刺耳，原因有据可查：4 次脉冲、950 Hz 带通、二极管 drive 1.6、默认 LEVEL 旋钮 122（`drum909.c:76, 322-333`）。SOFT 行提供三种模型：

- **SHAKER**（默认）：直接移植 808 Maracas（`drum808.c:682-712`）。噪声过两个一阶高通，起音软、衰减 10–300 ms，几乎不吃 CPU。
- **SNAP**：单次噪声脉冲（不是 4 齿），1.6–2 kHz 带通（Q 约 1.5），再过 5–6 kHz 低通，衰减 25–80 ms，不加 drive。默认电平比 SD 低约 10 dB。
- **BRUSH**：只用军鼓噪声，起音放慢到 8–15 ms，过低通。是"嘶"一声，不是"啪"一声，可以放在反拍上代替拍手。

三种都把 LEVEL 上限封在 SD 以下，也不提供 DRIVE。

### 3.3 键盘和屏幕

**原则**：黑键只有两种情况下才变成"操作键"：在 **DRUM 页**上，或者按住某个按钮的时候（按住层）。其他时候黑键照常弹音。

- **进入 DRUM 页**：用 ALGORITHM 选到 T3，再点 SEQ。现在的 `tap()` 会强制 `U.part = 0`（"SEQ is ACID's"，`dinghy.c:1427`），改成"part == 2 时进 DRUM 页"。SEQ 再点一下依次是：GRID 1–16 → GRID 17–32（长度超过 16 时才有）→ DRUM SEQ（LENGTH / SWING / FILL / KIT）。
- **在 DRUM 页上**：
  - 白键：切换选中行的这一步，和 ACID STEPS 页的手感一样，轻按 = 开或关（`step_key`，`dinghy.c:1227`）。
  - 黑键 1–10 选行；停止时按下会试听。黑键 11 选 AC 行，这时白键写重音。**这样不需要再借用 ENV 按住层**（ENV/EDIT 的按住层已经用来选轨和选预设了，`dinghy.c:1355-1359`）。
  - 开着 REC 并且在播放：黑键直接录入对应 voice，量化到当前步，和 X0X 一样。
  - OCT±：翻 1–16 和 17–32 步。
  - 四个旋钮：选中行的 TUNE / DECAY / TONE（SD 是 SNAPPY）/ LEVEL。
- **不在 DRUM 页时**选着 T3：键盘弹奏选中行的 voice，按半音变调。FUNCTION kit 下保持现在 kick 的音高逻辑。开着 REC 就写进选中行。黑键在这里只是普通的音。
- **按住层（允许黑键做操作）**：按住 GLO + 黑键 1–10 = 静音或取消静音某个 voice（现在 GLO 层只用了白键 1–4 静音四条轨，`dinghy.c:1328-1330`）。
- **EDIT（T3）**：第 1 页 KIT / ACCENT / DUCK / DRUM LVL；第 2 页是选中 voice 的 4 个旋钮（和网格页一样）。FUNCTION kit 下保留现在的 TONE / LEVEL 两页。
- **网格画法**：替换中间 240×108 的曲线区（58..166），做法和 `draw_steps` 一样（`dinghy.c:1639-1670`）。
  - 顶部 10 px 是状态条，例如 `909  ROW SD  1-16  HOLD:GLO+BLK=MUTE`。
  - 下面 11 行，每行 8 px（格子 13×6 px，行距 2 px），共 88 px。
  - **列和白键对齐**：`x = 2 + i×15`，和 STEPS 页一致，眼睛和手对得上。没有地方放左侧行名，所以只把选中的行整行高亮，行名写在状态条里。
  - AC 行用红色（REDC）小块；播放头所在的列用浅底色。
  - 底部 166..240 的四轨概览里，T3 那一行显示合并后的鼓点：BD 画高，其他画矮，有重音的更高。

### 3.4 存储（最先要定）

需要存的东西：

| 内容 | 字节 |
|---|---|
| 网格：10 行 × 32 步 bit + AC 32 bit | 44（只要 16 步就是 22） |
| 当前 kit 的音色：10 voice × 4 旋钮（TUNE / DECAY / TONE / LEVEL） | 40 |
| KIT、ACCENT、DRUM LVL（DUCK 和 LEVEL 可以复用 `kDuck` / `kLvl`） | 3 |
| **合计** | **约 87** |

切换 kit 时载入那个 kit 的默认音色（像预设一样），之后的调整存进这 40 字节。如果三个 kit 的音色都想记住，要 +80。

方案：

- **A（推荐 v1）**：把 `NSLOT` 从 7 减到 6。`params_t` 上限就变成 (4084 − 8) / 7 ≈ 582 B，472 + 88 = 560，放得下。不用改 platform，保存时仍然只擦一个扇区。代价是 U7 槽没了。读老存档要加迁移：按旧布局（472 × 8）读进来，丢掉 U7 并提示用户。新字段照 0.32/0.33 的做法加在结构体末尾，再在 `app_main` 的版本链里补一级回退（`dinghy.c:1745-1752`）。
- **B（以后要多个鼓 pattern 或 song 时）**：单独再用一个 4 KiB 扇区存鼓。8 份 × 87 B 绰绰有余，还能每个槽放好几个鼓 pattern。但 platform.c 现在只允许擦写设置扇区和升级暂存区（`fa:firmware/src/platform.c:71-72`），要放开一个扇区，**先查清楚 0xFC000 附近哪些扇区是真空闲的**，这一步是改 platform 的安全边界。
- **C（不推荐）**：硬塞进 37 字节余量里：8 行 × 16 步 = 16 B，加 AC 2 B、kit 2 B、每个 voice 的 LEVEL 和 TUNE 16 B，一共 36 B。之后就一点余量都没有了。
- 另一个可选的省法：KIT 不是 FUNCTION 时，把 `lane[2][32]`（kick 的音高 lane，32 B = 256 bit，正好是 16 行 × 16 步）复用成网格，零额外字节。代价是切换 kit 时要转换或者清空。

### 3.5 CPU、代码大小、RAM 估算

| 项目 | CPU（单核，估算） | 代码 / 闪存 | RAM |
|---|---|---|---|
| 现在的 FN ACID | 10–15%（`cpu_us` / `cpu_max` 已经在测，`dinghy.c:684, 838-840`） | 镜像 66.7 KB，XIP 上限约 568 KB（`fa:firmware/app.ld:13`） | pool 已用约 268 KB（delay 128 K + capture 128 K + reverb 12 K），上限 336 KB，剩约 70 KB |
| FUNCTION kit（新写，Q15） | +1–3% | +2–3 KB | <0.5 KB |
| 909 移植（FPU，-O2） | 普通 +5–7%，10 个 voice 同时响 +12–15% | 代码约 10 KB + 表约 14 KB + hh 采样 20 KB；要 ride 和 crash 再加 90 KB | 约 5 KB + 一块 256 个 float 的输出缓冲（1 KB） |
| 808 移植（FPU，-O2） | BD/SD/CH/CB 普通 +15–25%，带 CY/OH 最密 **+45%** | 约 8 KB，无采样 | 约 3 KB |

- RULES.md 要求 ISR 用时不超过一半预算。909 的最坏情况（15% + 15%）在范围内。808 的最坏情况（15% + 45%）超了，所以 v1 的 808 要么**不放 CY**（第 9 行换成 OH 长衰减或 CB），要么照 X0X 的过载保护在负载高时提高"安静"门槛，同时限制 CY 只能单发。
- 接法：每个 256 帧块开头先把整块鼓渲染进一个 float 缓冲（X0X 的 `drum909_render(d, dry, rev, dly, n)` 支持不开 send），然后在现有的逐采样循环里乘增益、转成 Q15 加进 `mix`。kit 切换和旋钮修改都在两个块之间做，和 X0X 的线程约定一样（`drum909.h:13-15`）。
- `-Os` 改 `-O2` 只对鼓这一个编译单元生效，做法和 X0X 的 `O2_UNITS` 一样。

### 3.6 哪些移植，哪些新写

**直接移植**（GPL 兼容，保留版权头）：

- `dsp/drum909.c/.h`、`drum909_dsp.h`、`fastmath.h`。删掉 pan、glide 和 send，只留单声道 dry。
- `tools/gen_drum_samples.py`，用来生成 tanh、指数曲线、μ-law 表和 hh 采样。`assets/909/hh.wav`（ride/crash 可选）。
- `dsp/drum808.c/.h`。可以只要 BD/SD/tom/clave/maracas/CB/hats，CY 先不要。
- 旋钮的工程单位换算和默认值（9W9/8W8 调好的，不要自己重新调）。

**新写**：

- KIT 切换和 10 行 voice 的映射；把我们 `PM[]` 里 0..127 的值接到 `drum909_set` / `drum808_set`。
- SOFT 行的 SNAP / BRUSH（SHAKER 可以移植 Maracas）。
- FUNCTION kit 的 SD / toms / RS / CY / CB（整数）；把 T4 噪声镲抽成共用函数。
- DRUM 页的网格、按键逻辑、GLO 按住层的静音。
- 存储方案 A 和存档迁移；BD 触发闪避；float 块转 Q15 混音。

**不需要**：X0X 的 fxbus、master、sequencer、motion、project/lz 存储，以及 ui.c（可以参考，不用搬）。

**如果 FPU 验证没通过**：909 改成定点还可行。积木都简单：三角波相位、双二阶用 Q30 系数 + int64 乘法（RULES 允许 64 位乘、禁 64 位除）、tanh 表做成 Q15。808 难：50 Hz 附近的高 Q 桥 T 带通，连 float 都要用 e1/e2 的技巧才保得住精度（`drum808.h:42-45`），定点更难。所以无论哪种情况，**都先做 909，808 放到第二步**。

### 3.7 建议顺序

1. 写一个 10 行的 FPU 冒烟测试：给一个单元加 `-mfprev1` 编译，在 ISR 里做 float 运算，上机看结果对不对、`cpu_us` 多少。
2. 定存储方案 A，加存档迁移。
3. FUNCTION kit 加 10 行网格和 DRUM 页（不依赖 FPU，可以先上机看手感）。
4. 移植 909：先 BD/SD/CH/OH/RS + SOFT=SHAKER，再加 toms / 采样镲。
5. 移植 808 精简版（不带 CY），在负载最高的 pattern 上量 `cpu_max`。
